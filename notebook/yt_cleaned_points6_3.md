- New message types to be aware of: BaseMessage, ToolMessage, and SystemMessage.
- ToolMessage is a message type used to pass data back to the LLM after a tool call; it typically contains the content produced by the tool and a tool call ID.
- SystemMessage is used to provide instructions to the LLM, e.g., "You are a helpful assistant."
- BaseMessage is the foundational (parent) class for all message types in Langraph; AIMessage, HumanMessage, ToolMessage, SystemMessage, etc., are child classes that inherit BaseMessage properties and add their own fields.
- Think of BaseMessage as the base class that defines common properties, and specific message types add fields like tool_call_id or role-specific content.

- Tools and tool nodes are elements you previously learned about and will use to expose executable functions to the LLM.
- Example import: from langraph.dossage import add_messages — add_messages is a reducer function used to control how node updates combine with existing state.
- A reducer function defines the rule for how updates from nodes merge with the existing state; it decides whether to overwrite, append, or otherwise combine new data with current state.
- Without a reducer function, updates would typically replace the existing value and could unintentionally discard prior state.
- Example demonstrating overwrite vs aggregation: initial state messages = ["hi"]; an incoming update "nice to meet you" would overwrite without a reducer but would be appended to produce ["hi", "nice to meet you"] when using a reducer like add_messages.
- add_messages is a reducer function that aggregates message updates into the state so messages are appended instead of overwritten.
