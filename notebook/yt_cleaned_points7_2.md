- We already know `TypedDict`, but we have not yet come across `Annotated` or `Sequence`.
- These are also type annotations.
- `Annotated` provides additional context to your variable or key without changing its actual data type.
- For example, suppose I create a `TypedDict` with an `email` key.
- The email is a string, so I would normally write `email: str`.
- But some keys, like email, need to match a certain format.
- For example, it should be something like `abc@gmail.com`.
- If I pass `abcd-gmail.com`, that is not a valid email format, but it is still technically a string.
- So it would pass through.
- `Annotated` helps solve that problem.
- You first pass the data type you want, such as `str`.
- Then in quotation marks, you add additional context.
- That extra context becomes metadata for the key or variable.
- For example, you could specify that it must be a valid email format.
- If I want to see the metadata, I could print the email metadata.
- If I run it, it shows the message that it must be a valid email format.
- That is what `Annotated` does.
- `Sequence` is also a type annotation.
- It automatically handles state updates for sequences, such as adding new messages to chat history.
- It avoids list manipulation inside graph nodes.
- In graph and node systems, there is often a lot of list manipulation when updating state.
- `Sequence` handles much of that.
- You do not need to worry about it too much.
