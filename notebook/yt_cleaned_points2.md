- The first section covers type annotations and is theoretical but short; type annotations will appear frequently when coding Langraph agents and graphs.
- Dictionaries in Python are a data structure with key/value pairs; example: a simple dictionary called movie with keys "name" and "year" and values "Avengers Endgame" and 2019.
- Dictionaries enable efficient retrieval by unique keys and are flexible and easy to implement.
- A potential problem with plain dictionaries is ensuring that the data conforms to a particular type or structure, which can cause logical errors in large projects.
- The solution is using a TypedDict (type dictionary) to enforce structure and types.
- A TypedDict in Python is implemented as a class where each key is declared with an expected data type.
- Example TypedDict: a class representing movie with name: str and year: int, initialized with "Avengers Endgame" and 2019.
- Benefits of using a TypedDict include type safety (explicitly defined contents reduce runtime errors) and improved readability and debuggability.
- Union is a type annotation that specifies a value may be one of several types.
- Example: a function square that accepts x annotated with Union[int, float] accepts integers or floats and will fail for strings.
- Union is used extensively in libraries such as LangChain and Langraph to provide flexibility while preserving type safety.
- Optional is a type annotation that allows a value to be either a specified type or None.
- Example: a function nice_message(name: Optional[str]) that greets a given name or, if None, prints a fallback like "hey random person".
- Optional restricts the parameter to either the specified type or None, not to other types like int or bool.
- Any is a type annotation meaning the value can be any data type.
- Example: a function print value that accepts Any and prints the value; strings, numbers, lists, or any type are allowed.
- Lambda functions provide concise inline function definitions for small operations.
- Example 1: a previously defined square function that returns x * x and square(10) returns 100.
- Example 2: using map with a lambda to square each element in nums: map(lambda x: x * x, nums) converted to a list yields [1, 4, 9, 16] for nums = [1,2,3,4].
- Lambda functions are a shortcut for small functions and can be more efficient and concise than a for loop for simple transformations.
- No need to memorize all type annotations immediately; have a high-level understanding because they will appear when coding Langraph.
- The next section covers Langraph elements; begin with the state.
- A state is a shared data structure that holds the current information or context of the entire application.
- The state is analogous to an application's memory where variables and data that nodes can access and modify are stored.
- Analogy: a whiteboard in a meeting where participants (nodes) write or update information; the whiteboard is the state.
- Nodes are individual functions or operations that perform specific tasks within the graph.
- Each node receives input, often the current state, processes it, and produces an output or an updated state.
- Analogy: assembly line stations where each station performs one job; each station represents a node.
- The graph is the overarching structure mapping how nodes are connected and executed; it visually represents workflow sequences and conditionals.
- Analogy: a roadmap showing routes and intersections where intersections offer choices on which path to take.
- Edges are connections between nodes that determine execution flow and indicate which node runs next after the current one completes.
- Analogy: train tracks connecting stations; the train represents the state being carried and updated between stations (nodes).
- Conditional edges are specialized connections that decide the next node based on conditions or logic applied to the current state.
- Analogy: a traffic light deciding whether to go, stop, or slow down; conceptually similar to an if/else statement.
- The start node or start point is a virtual entry point that marks where workflow execution begins; it does not perform operations itself.
- Analogy: starting line of a race.
- The end node signifies the conclusion of the workflow; when reached, graph execution stops.
- Analogy: finish line of a race.
- Tools are specialized functions or utilities nodes can use to perform tasks such as fetching data from an API.
- Tools enhance node capabilities by providing additional functionality; they are distinct from nodes because tools are utilities used within nodes.
- Analogy: tools in a toolbox like a hammer or screwdriver, each with a specific purpose.
- A tool node is a special node whose main job is to invoke a tool and inject the tool's output back into the state.
- Analogy: an operator (tool node) controlling a machine (tool) and sending results back to the assembly line.
- The state graph is an element that builds and compiles the graph structure, manages nodes and edges, and ensures unified workflow operation and correct data flow.
- Analogy: a building blueprint that outlines design and connections; the state graph defines structure and flow of the application workflow.
- A runnable is a standardized executable component that performs a specific task within an AI workflow and acts as a modular building block.
- Difference between runnable and node: a runnable can represent various operations, whereas a node typically receives a state, performs an action, and updates the state.
- Analogy: runnables are like Lego bricks that snap together to build complex structures.
- Langraph uses five common message types similar to LangChain: human message (user input), AI message (model-generated responses), system message (instructions or context for the model), tool message (tool-specific message similar to function message), and function message (represents a tool or function call).
- Users familiar with LLM APIs such as OpenAI's API will recognize system, AI, and human messages.

- Docstrings in Langraph are important because they tell LLMs what a function does when building AI agents later.
- Example docstring: "simple node that adds a greeting message to the state."

- Create the graph by instantiating state graph with the state schema agent state and store it in a variable such as graph.
- Add the greeting node to the graph using graph.add_node with two main parameters: the node name (e.g., greeter) and the action function (greeting_node).
- Set the entry point using graph.set_entry_point("greeter") and set the finish point using graph.set_finish_point("greeter") to connect start and end to the same node.
- Compile the graph using graph.compile and store the compiled graph in a variable such as app.
- Compiling without errors does not guarantee the graph will run correctly; logical errors can still exist.
- Use IPython visualization code to display the graph structure; the node name in the visualization matches the name provided when adding the node (e.g., greeter).
- Invoke the compiled graph using app.invoke and pass the initial state with message value, for example message: "Bob", storing the result in a variable.
- Access the output state attribute result by referencing result.message to retrieve the updated message "hey Bob how's your day going" based on the greeting node logic.
- The entire flow demonstrates how a node reads the state, updates it, and the updated state is returned by the graph.
